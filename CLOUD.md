# Запуск без ноутбука: GitHub и Railway

GitHub хранит исходники. Railway запускает программу и принимает сообщения
Telegram, даже когда ваш ноутбук выключен. Google Таблица остаётся той же.
Этот пакет подготовлен для облачного запуска; перенос работающего бота ещё не выполнен.

## 1. Загрузить исходники на GitHub

1. Распакуйте `telegram-schedule-bot.zip`.
2. Откройте https://github.com/M0rfick/shield под аккаунтом, у которого есть право
   записи в этот репозиторий. Сейчас у подключения помощника есть только чтение.
3. Нажмите **Add file → Upload files**. В пустом репозитории можно нажать
   **uploading an existing file**.
4. Перетащите содержимое распакованной папки. `bot.py` и `Dockerfile` должны
   оказаться в корне репозитория. Загружайте файлы из нового архива, а не всю
   папку работающего бота: в ней есть локальные ключи и состояние.
5. Нажмите **Commit changes**. GitHub нужен распакованный код, не один ZIP.
   Если скрытые файлы не видны в Finder, нажмите **⌘⇧.**.

В архиве нет токена, `.env`, `state.json` и журналов. `.env.example` содержит
только пустые поля и пример разрешённых имён. Репозиторий `M0rfick/shield` публичный.

## 2. Подготовить сервер

1. Откройте https://railway.com и войдите. Вход, подключение GitHub и условия
   сервиса подтверждаются в вашем аккаунте.
2. Создайте проект из GitHub-репозитория **M0rfick/shield**. Если Railway просит
   доступ к GitHub, выберите этот репозиторий.
3. Railway обнаружит `Dockerfile`. Корневая папка — `/`; команда запуска уже
   указана в файле. Порт и публичный домен этому боту не требуются: он сам
   запрашивает сообщения Telegram.
4. До запуска добавьте **Volume** к сервису с точкой подключения `/data`.
   В нём сохраняются номер последнего сообщения, подгруппы и привязки участников.
5. В **Variables** заполните настройки из таблицы ниже. Ключи вводятся здесь,
   а не в GitHub. Не публикуйте снимки экрана с заполненными ключами.
6. Оставьте **одну копию** сервиса (Replicas: 1), выключите засыпание
   (Serverless/App Sleeping, если оно включено), включите перезапуск при сбое.
   Не настраивайте периодический запуск: бот должен работать постоянно.

| Настройка | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен вашего @Schedule3112bot |
| `SHEETS_WEB_APP_URL` | Текущий адрес подключения Google из локального `.env` |
| `SHEETS_SHARED_SECRET` | Текущий секрет подключения Google из локального `.env` |
| `AUTHORIZED_USERNAMES` | `Ivan_Morfick,zxcWenty,Shcherbakov_23` |
| `BOT_STATE_PATH` | `/data/state.json` |

`BOT_STOP_FILE` на сервере оставьте незаполненным. Секреты и Google-скрипт
повторно создавать не нужно. Цена Hobby — $5 в месяц, включая $5 использования
ресурсов; при превышении этой суммы начисляется разница. До выбора платного
тарифа проверьте текущую цену и лимит расходов в аккаунте.

## 3. Переключить бота

Сначала подготовьте файлы, диск и настройки сервера. Не запускайте облачную
копию с тем же токеном одновременно с работающей копией на ноутбуке.

1. Остановите работающую копию на ноутбуке и дождитесь завершения.
2. Для сохранения настроек перенесите локальный `state.json` на постоянный диск
   сервера по пути `/data/state.json`. Делайте это приватно через управление
   файлами Volume; в GitHub и публичный архив этот файл не добавляется.
3. Запустите сервис (**Deploy**). В журнале должны появиться сообщения:
   «Бот @Schedule3112bot запущен» и «Получение сообщений Telegram работает».
4. Отправьте боту `/start`, проверьте расписание и предварительный просмотр
   отметки, затем отмените просмотр. Для проверки связи не требуется записывать
   выдуманный пропуск в настоящую таблицу.
5. После этой проверки ноутбук можно выключить. Локальную копию не запускайте,
   пока работает облачная. При следующем обновлении кода Railway сможет
   перестроить приложение из GitHub.

Если возник конфликт двух копий, остановите одну и перезапустите другую.
Если у сервиса нет постоянного диска, настройки могут теряться при обновлении.

Образ контейнера здесь подготовлен, но локальная сборка не выполнялась:
на этом ноутбуке нет Docker. Сборку нужно проверить при первом облачном Deploy.
